Rentra — end-to-end project flow

Repository-based map of how web/mobile clients connect to backend modules, Prisma, PostgreSQL, and external services.

Web

React + TypeScript + Vite. Pages call API helpers through Axios; signed-in requests attach a bearer token.

Backend

NestJS + Express REST API under /api. Controllers, DTO validation, guards, services, and shared Prisma access.

Mobile

Expo/React Native starter with auth and role home screens. It calls the same API; most full marketplace flows are currently web/backend-side.

AI today

Python FastAPI service currently exposes only /health. The web Fake Detector page displays admin-confirmed reports; automated scanning is not implemented.

Typical request path

  • Browser/mobile screen collects input and invokes an API helper.
  • Axios calls the shared NestJS API and attaches an access token when signed in.
  • JWT/role guards and DTO validation check the request.
  • Feature service applies business rules, then Prisma reads/writes PostgreSQL.
  • API returns JSON; clients refresh the screen/state.

Property to rental lifecycle

  • Landlord submits property details; backend resolves location and creates a pending-verification property/listing record.
  • Images go through the backend upload route to Cloudinary; image metadata/URLs are stored in PostgreSQL.
  • After moderation/publication, tenants browse, search, save, and submit rental requests/bookings.
  • Agreements, payments, reviews, reports and audit events are managed by separate backend modules.

Current integration limits

  • Prisma is the database access layer; migrations/schema are in packages/database/prisma.
  • Cloudinary handles listing/property images. Gmail SMTP credentials are used by the email service.
  • Payments has an adapter interface, but the module registers an empty adapter list, so a real payment provider is not connected.
  • No Redis/cache or live WebSocket infrastructure is represented in the current app wiring.

AI: future use, not current behavior

  • Potential API integration: listing risk signals, rent-price estimates, search ranking, and document triage.
  • Keep AI as a recommendation/flagging layer; require admin review for consequential moderation.
  • Current FastAPI service has health-check only; AI calls/models, datasets, and inference pipeline still need to be built and connected.

Source: repository structure, Nest AppModule, web/mobile API clients, Prisma schema and AI service entry point. This describes code present in the workspace, not a production deployment topology.
